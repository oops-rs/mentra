# mentra v0.11.0

Mentra 0.11 adds automatic tool-result paging: a built-in answer to tool
results whose size the agent loop cannot control — above all third-party MCP
servers. The feature is opt-in per agent; every existing consumer is
byte-identical until it enables it.

Design and as-built record:
[tool-result-paging](https://github.com/oops-rs/mentra/blob/v0.11.0/docs/tool-result-paging.md).

## Highlights

### Automatic tool-result paging

- `AgentConfig.tool_result_paging: Option<ToolResultPagingConfig>` (default
  `None`). With paging enabled, a result above `threshold_bytes` (default
  64 KiB) inserts only its first window (default 32 KiB, cut on a line
  boundary) plus an honest trailer:

  ```text
  …[paged: lines 1–812 of 5,723 (64.0 KB of 410.3 KB). Call
  read_tool_result(tool_use_id="call_8", start_line=813) for the next
  window.]
  ```

- The built-in `read_tool_result(tool_use_id, start_line)` tool serves
  further windows from full results retained per agent. Line numbers are
  absolute over the whole result on every window, so quoted or cited lines
  survive paging unchanged. The tool never re-executes the original tool,
  never pages its own windows, and resolves its store from the calling
  agent's context — a cross-agent read is not expressible.
- `AgentEvent::ToolExecutionFinished` keeps carrying the complete, unpaged
  result. Paging shapes the model's view, never the event record: hosts that
  rebuild evidence, ledgers, or telemetry from the event stream observe no
  change whatsoever.
- The transform applies at the single point where a round's results are
  collected, downstream of the universal tool-result limiter introduced in
  0.10. A consumer enabling paging should raise
  `max_tool_result_bytes`/`max_tool_result_lines` to what its tools may
  legitimately return, keeping the limiter as the anti-abuse backstop.

Motivating incident: a production host ran a log-retrieval MCP server whose
eighteen fetches accumulated 1.82 MB of tool results in one worker context and
died on `context_length_exceeded` before the run could finish. With paging,
the same run holds one window per result in context and reads deeper only
where the evidence warrants it.

### Team

- Team protocol request ids are collision-resistant.

## Compatibility

- No breaking API changes. `AgentConfig` gains one optional field; all other
  additions are new types and one new built-in tool name
  (`read_tool_result`), offered only to agents that enable paging.
- mentra-provider remains at 0.4.1; no provider changes in this release.
